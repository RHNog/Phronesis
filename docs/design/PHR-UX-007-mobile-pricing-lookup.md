# PHR-UX-007 Designer Direction

The Pricing Lookup is a focused mobile field instrument inside Decide, not a dashboard or recommendation system. Search stays available above category freshness. Relevant sealed matches appear in a labelled group above singles, initially capped at two on narrow screens, while a sticky `Singles condition` control visibly governs singles only. Each compact result reads product type, exact printing identity, delivered price, listing and shipping, history, and snapshot date in that order.

Use the approved zinc/cyan Phronesis language, 16px phone gutters, one-column scan order below 768px, bounded content above it, 44px controls, semantic lists and headings, visible focus, text-backed statuses, stable loading geometry, polite live updates, reduced-motion support, and reflow through 400%. Sealed rows always say `Sealed · no condition`; missing sealed shipping means `Delivered price unavailable` and `Shipping unknown`. Missing selected single condition says `No listing in this condition` and labels the nearest priced grade separately. Never use recommendation colors, scores, decorative charts, or values that conceal missing data.

Required responsive evidence widths are 320, 768, 1200, and 1440 CSS pixels. Jarvis Mac Worker—not Engineering—must capture rendered, keyboard, screen-reader, contrast, zoom, reduced-motion, and increased-contrast evidence after a runnable target exists.

Completed Worker output must pass the repository-owned evidence validator before manifest statuses may support conformance. Summary counts, generic assertions, raw accessibility dumps, and manifest `pass` labels cannot substitute for structured zoom measurements or the pruned semantic sequence.

The evidence-only development runtime suppresses the Next.js development indicator. Framework chrome may not cover controls, history, freshness, or snapshot text. A stale scenario uses one coherent snapshot date for the category freshness label and all visible priced results.

At 200% and 400% desktop browser zoom, both search and the Singles condition control return to normal document flow instead of covering a result. Ordinary phone layouts keep the approved sticky field controls. Both zoom captures must visibly preserve the first result's product-type label, name, and printing identity; horizontal-overflow checks alone are insufficient.

The reflow state must remove sticky positioning from both field controls structurally, not merely override their computed positions while leaving sticky utility markers on the rendered elements. Worker diagnostics must confirm both reflow markers are active and both sticky classes are absent.

The same diagnostics must confirm search and the condition panel both compute to `static`, and neither obscures decision content in the desktop-zoom evidence state.

For each zoom level, the diagnostic payload must include each control's reflow marker, full class list, sticky-class presence, computed position, and bounding rectangle; each visible result identity's non-empty product type, name, printing identity, visibility, and bounds; explicit search/result and condition/result intersection outcomes; and viewport/scroll overflow measurements.

Each result identity is selected uniquely by its repository-provided SKU probe. Control selectors must match exactly one visible element. Identity capture must contain at least one item and include non-empty product type, name, printing identity, whole-result bounds, and individual field bounds. A pass with null controls, empty identities, missing bounds, or omitted control/identity intersection pairs is invalid regardless of a reported zero intersection count.

Keyboard and focus evidence must expose the lookup field as `Search card, set, collector number, or sealed product` and the selector as `Singles condition`. Web reading order is captured only from the labelled `Price lookup` region at `.pricing-lookup`, prunes raw `StaticText` and `InlineTextBox` descendants, excludes Next.js development tooling, and derives one clean spoken sequence from exposed semantic nodes. The serialized Worker may obtain the page-target full accessibility tree, but it must resolve the region's backend node first and retain only that matching region plus descendants reachable through accessibility `childIds`; document ancestors, siblings, and unrelated runtime nodes are invalid evidence.

Each visible web result must contribute an intelligible semantic summary naming product type, product name, full printing identity, delivered-price state, listing and shipping breakdown, history, and snapshot date. Native result cards must keep those facts separately traversable; one combined card utterance is invalid because host speech may truncate it. The native transcript must contain the full variant names and all required decision facts without clipped endings.

The desktop evidence host opens explicit `zoom=200` and `zoom=400` non-shipping evidence scenarios because emulated pointer and screen metrics are not stable zoom signals. Those scenarios place both field controls in normal flow. Ordinary narrow phone evidence keeps the sticky field interaction.

Native evidence must include representative compact- and large-iPhone baseline captures at the standard `large` content-size category with increased contrast disabled. Accessibility-extra-extra-extra-large Dynamic Type with increased contrast is a separate large-iPhone environment capture and cannot substitute for the baseline layout.

The compact native evidence run may scroll to the sealed expander, whose label must expose a genuine 44-point hit target and whose action toggles between `Show all 3 sealed products`/`collapsed` and `Show fewer sealed products`/`expanded`. The bounded gesture must use settled interior coordinates in the owning `ScrollView`; short gestures that leave the scroll position unchanged are invalid. Scrolling can invalidate the original SwiftUI accessibility snapshot, so activation must use a freshly resolved, hittable `collapsed` control. Since expansion then inserts a card before and repositions the control, state verification must re-resolve it again instead of retaining the pre-mutation snapshot. The evidence is invalid if repeated gestures leave the expander below the viewport or activation never exposes the expanded state.

The bounded evidence handoff consists of the `/price-lookup` Next.js route, deterministic non-shipping `/price-lookup/evidence` scenarios, the non-shipping `ios/PhronesisEvidence.xcodeproj` application/UI-test host, and `tests/jarvis_runtime_evidence.py`. The evidence surfaces mirror required hierarchy and named controls only for Mac Worker capture; they do not add fixture data or a native application to product scope.
